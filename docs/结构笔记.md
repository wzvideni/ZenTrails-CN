# 逆向笔记：界面结构、几何常量与调试工具

这份文档记录汉化过程中摸清的界面事实，主要是给以后（或者别的想改这个游戏 UI 的人）省时间用的。

## 环境

| 项 | 值 |
|---|---|
| 游戏 | Zen Trails（Steam），仅 Windows |
| 引擎 | Unity **2019.1.8f1**，Mono 后端 |
| UI | UGUI + **TextMeshPro 1.4.0** |
| 分辨率 | 1920×1080 无边框窗口，客户区坐标 = 屏幕坐标 |

## 信息气泡（SegmentInfoPanel）

选中一段轨迹后弹出的那个气泡：

```
InfoPanelsCanvas
└─ SegmentInfoPanel                    ← 气泡整体，关闭时 localScale = 0，打开时 ×1
   ├─ SpeedText   (速度)
   ├─ LengthText  (长度)
   ├─ AngleText   (角度)
   ├─ MoreButton  (更多)                ← 展开下面的美学面板
   └─ AestheticsPanel                  ← 面板自身 RectTransform 为 100×100
      ├─ LineThickness  (粗细)          行：标签 + InputField(TMP) + ＋/－/? 按钮（都是它的子物体）
      ├─ Glow           (辉光)
      ├─ LayerOrder     (图层顺序)
      ├─ LimitRotationsOption
      └─ GradientPicker / FlexibleColorPicker …
```

几个容易踩的点：

- 气泡对象在进入编辑器时就已创建，**一直存在**，只是 `localScale = 0`。所以"第一次打开错位、第二次打开正常"这类现象，都是因为偏移量被写在了同一个组件实例上。
- 每一行的 **数值框、＋/－/？按钮都是该行标签 GameObject 的子物体**，所以移动数值框要动子物体，并按 `localScale.x` 反向补偿。
- 气泡里只有一个 `AestheticsPanel`。另有一处同名节点 `Canvas/SettingsPanel/ModifyAllButton/.../SetAllToSameValuePanel/LayerOrder`（全局修改面板），结构不同，插件没有碰它。

### 实测几何（面板局部坐标，面板 100×100）

| 行 | rect 尺寸 | localPosition | localScale | 数值框左边缘 |
|---|---|---|---|---|
| `LineThickness` | 86.3 × 50 | (−31.7, −44.3) | 0.1554 | **−26.44** |
| `Glow` | **−**182.1 × 50（镜像） | (−11.0, −86.1) | 0.1554 | **−26.72** |
| `LayerOrder` | 342.3 × 50 | (−25.8, −126.9) | 0.126 | **+4.38** |

原始字形范围（char 级）：

| 行 | 左 | 右 |
|---|---|---|
| 粗细 | −120.15 | −79.45 |
| 辉光 | −79.12 | −37.89 |
| 图层顺序 | −113.20 | −32.05（char 级 −32.43） |

结论：三行数值框本来不在同一列（−26.44 / −26.72 / **+4.38**），把 `LayerOrder` 的框平移 **−31.10** 就能三列合一，公共列 ≈ **−26.7**。

## 补丁算法（plugin/ZenTrailsCN.cs）

1. `Scan()`：周期性用 `Resources.FindObjectsOfTypeAll<RectTransform>()` 找名字为 `AestheticsPanel` 且三个行子物体齐全的节点（不要求 active）。前 600 帧每 15 帧扫一次，之后每 180 帧。
2. 在**面板局部坐标系**里量：沿 `localPosition / localScale` 逐级上溯换算出面板空间坐标。这一步是关键 —— 不依赖真实渲染，面板还缩在 `localScale = 0` 时就能算，所以可以做到"第一次打开就已经对齐"。
3. `AlignOnce()`：
   - `LayerOrder` 的框先平移 `−31.10` 补进公共列；
   - 标签字形用 TMP 的 `margin.x` 移动，同时写**等量反向的 `margin.z`**，保证文字区域宽度不变（只改 `margin.x` 会让"图层顺序"折成两行）；
   - `margin → 面板单位` 的比例 **k 是每行实测的**（`(r1−r0)/100`，粗细/辉光约 `0.1554`，图层顺序 `0.126`），不写死。
4. 目标：标签右边缘 = 公共列 − `Gap(6)` = **−32.72**。
5. 同一帧内最多迭代 6 次 `AlignOnce`，避免出现中间态。
6. `Check()`：文本或面板尺寸签名变化时重算；面板从收起到展开的那一帧也重算一次。

### `LayerOrder` 是个特例

这一行的 `fontSize` 是 163.39（另两行 133.88），且 `characterInfo` 量出来的字形范围比实际渲染**偏右约 31 px**，原因没完全查清（怀疑是 TMP 1.4.0 对镜像/超大 margin 组合的 characterInfo 计算与实际布局不一致）。所以这一行不走测量回路，直接用标定好的常量：

```csharp
private const float LayerOrderMarginX = -270f;
private const float LayerOrderMarginZ = -262f;
```

换成别的版本/分辨率时需要重新标定：先把另外两行对齐，再看这一行偏移多少，等比调这两个值。

## 字体

- 中文来自 TMP 字体包里的 Arial Unicode 生成的 SDF 资产 `arialuni_sdf_u2019`，在 `AutoTranslatorConfig.ini` 中设
  `FallbackFontTextMeshPro=arialuni_sdf_u2019`，即**只在缺字形时回落**，英文仍用原字体。
- 图集里没有全角标点（U+FF00 区块）和 U+2018-201F 弯引号，`tools/build.py` 的 `NORM` 会把它们换成半角形式或直角引号。
- `translation/font_chars.json` 存的是图集里真实存在的字形，用来在生成阶段拦下会变方块的译文。

## 调试插件 ZenDump（不随包发布）

`plugin/ZenDump.cs` 是开发时用的插件，装到 `BepInEx\plugins\ZenDump.dll` 后：

- **F9**：把当前界面的 UGUI/TMP 树 dump 到 `BepInEx\dump_texts.txt`
- **F10**：诊断信息（焦点、指针是否在 UI 上等）→ `BepInEx\diag.txt`
- **F11**：读 `BepInEx\click_req.txt`（一行一条命令），执行结果写 `BepInEx\click_log.txt`

F11 支持的命令：

| 命令 | 说明 |
|---|---|
| `click:<路径子串>[:all]` | 找 Button 并 `onClick.Invoke()`，`all` 表示全部命中都点 |
| `click=<精确路径>` | 精确路径点击 |
| `props:<路径子串>` | 打印命中 TMP 的 rect / margin / 字形范围等属性 |
| `freeze:<路径子串>` | 把 `localScale` 强制为 1 并禁用上层 InfoPanel（把收起的面板强行显示出来调试） |
| `show:<路径子串>` / `toggle:` | 显隐切换 |
| `text:<路径子串>\|<新文本>` | 直接改文本，用来测长数字/换行 |
| `types:<正则>` / `find:<类型名>` / `call:` / `callat:` | 反射相关（部分操作会抛异常，慎用） |

配合 `tools/ctl.py` 使用（先 `uv sync`，脚本一律用 `uv run` 跑）：

```powershell
uv run python tools\ctl.py cap  out.png              # 用 GDI PrintWindow 抓窗口（比如桌面截图接口失效时）
uv run python tools\ctl.py click 960 425             # 客户区坐标点击
uv run python tools\ctl.py key 7A                   # 按 F11 = 0x7A
uv run python tools\ctl.py drag 700 700 1100 500     # 默认右键拖动（画轨迹）
```

## 输入上的坑

- **注入的鼠标点击经常被游戏忽略**：`SendInput` / `mouse_event` 造的点击有时生效、有时不生效，启动后的第一次点击几乎必被吞（多半被吞在窗口获得焦点的那一次）。所以验证时**多点几次**，或者干脆用 F11 走 UI 事件（`onClick.Invoke()`）。
- **键盘一直可靠**：`key` / `seq` 走键盘的方案最稳。
- 抓图优先 `ctl.py cap`（GDI），比从桌面截图稳定，也不会带上鼠标指针。
